# 项目重构专家

## 什么时候用
用户要把项目换语言（Kotlin → Rust、PHP → Go 之类）、换架构（分层、拆模块、抽接口）、
或者对着一个乱工作区说「先看清楚再动手」。**不要一上手就改代码**，先建索引再看。

## 固定流程（顺序不能跳）
1. **`rf_scan`**：扫一遍工作区，生成 `.docs/function.txt`、`.docs/imports.txt`、`.docs/index.txt`。
   一次两三秒，改完代码要重跑。构建产物、依赖缓存、下划线开头的第三方目录自动跳过。
2. **看 `index.txt`**：几万行？哪种语言最多？入口在哪？最大的文件是哪些（上帝文件）。
3. **`rf_plan`**：`mode=lang` 换语言 / `mode=arch` 换架构，写出 `.docs/refactor.txt` 六步计划。
4. **按计划一步步做**：一次只碰一个文件 / 一个模块，做完立刻编译，绿了再进下一步。
5. **动手前两次确认**：`rf_refs`（谁 import 它）与 `rf_deps`（它 import 谁），别凭印象。
6. 收尾：删残留、换构建脚本、重跑 `rf_scan` 刷新索引。

## 三条纪律
- 一次只做一件事。翻一个文件就编译；搬一个模块就跑一次真实入口。不要攒一堆改动再验证。
- 每一步都能单独回滚。改动大就分多次提交，别让人替你猜哪步坏了。
- 先查索引再动手。`rf_grep` 能定位到文件就别全文 grep；`rf_refs` 能确认引用就别猜。

## 查关系的两个方向
- 反查「谁引用我」：`rf_refs(ws, target)`。先看 `imports.txt`，再用类名整词搜源码兜底
  （Kotlin 同包调用、`b.ai.core.Sum.llm()` 这种全限定名不会出现在 import 里）。
- 正查「我依赖谁」：`rf_deps(ws, file)`。输出分三种：内部（对上工作区文件）、
  项目内（同项目但类定义在别的文件里）、外部（三方库）。

## 参数怎么填
- `ws` 带绝对路径，一般是当前工作区根目录。
- `target` / `file` 可以给相对路径，也可以只给文件名；不确定就先 `rf_grep` 或 `rf_show` 查。
- `mode` 只能是 `lang` 或 `arch`。
- `doc` 只能是 `function|imports|index|refactor`，`page` 从 1 开始，每页 100 行。

## 别做的事
- 不要在没建索引的情况下批量改文件——你看不见引用关系，改完编译不过还得回滚。
- 不要把 `function.txt` 整份塞进上下文，用 `rf_grep` 定位、`rf_show` 翻页。
- 不要替用户决定换还是不换：换语言 / 换架构是两条完全不同的路，问清楚再 `rf_plan`。
